# Privacy and security requirements

## Authority and use

This document is a focused canonical module within [Quality, security, and operations requirements](README.md) and the authoritative requirements baseline indexed by [Project requirements](../../PROJECT_REQUIREMENTS.md). The index defines status vocabulary, priority semantics, ID stability, and precedence. This file describes planned behavior, not implemented behavior; each identified row's recorded status controls.

## Privacy and security

**MVP decision status:** The Accepted MVP data boundary is limited to project-owned synthetic fixtures and minimized run records stored on the developer's machine. [ADR-0016](../../architecture/decisions/ADR-0016-filesystem-run-persistence.md) defines one deletable run directory as the persistence unit. [ADR-0014](../../architecture/decisions/ADR-0014-groq-as-mvp-external-generation-provider.md) permits one explicit Groq generation request only when the user selects Groq for that run; it does not relax the local-only path. Hosted tracing, LangSmith, telemetry, analytics, cloud persistence, and automatic fallback are Deferred. This 2026-08-25 boundary narrows the earlier REQ-SEC-006 cascading-deletion concept and the earlier REQ-SEC-011 whole-suite zero-egress proposal.

Deleting the local directory must not be presented as erasing any independently retained provider record. | Must | Accepted | Exact-directory deletion and claim check |
| REQ-SEC-007 | A public demonstration must use synthetic or explicitly approved non-sensitive fixtures and data. | Must | Accepted | Release inspection |

| REQ-SEC-010 | Tombstones, append-only deletion ledgers, cascading lineage repair, and recoverable deletion history are Deferred pending a demonstrated retention or recovery need. | May | Deferred | Scope review |
| REQ-SEC-011 | Deterministic scanning, retrieval, review, comparison, and local generation must use only enumerated loopback endpoints and must work with non-loopback egress disabled. A user-selected Groq generation request is the only MVP workflow exception and may contact only the approved Groq HTTPS destination. Framework analytics, update checks, crash reporting, and unrelated network calls remain disabled. | Must | Accepted | Mode-specific network inspection |
| REQ-SEC-012 | Reproducibility records and content-safe diagnostics must remain local and provider-neutral. LangSmith and every other hosted tracing, telemetry, or analytics service are outside the MVP. | Must | Accepted | Offline record inspection |
| REQ-SEC-013 | The Groq API key must be loaded only by the local service from an ignored local `.env` file or an equivalent local secret mechanism. The actual secret must never enter browser code, Git, tracked documentation or examples, evidence, prompts, run JSON, reports, logs, diagnostics, exports, or persisted provider responses. | Must | Accepted | Secret-flow and repository inspection |
| REQ-SEC-014 | The Groq adapter may contact only the approved Groq HTTPS API destination. The local adapter may contact only the approved loopback runtime. Arbitrary custom endpoints, a second external provider, and browser-originated provider calls are outside the MVP. | Must | Accepted | Endpoint and renderer-boundary inspection |
| REQ-SEC-015 | A Groq request may send only the minimized synthetic finding evidence and curated guidance passages required for the structured proposal, plus the application-owned instructions and schema. It must not send raw HTML, DOM snapshots, screenshots, credentials, cookies, input values, private URLs, hidden page data, unrelated corpus content, or prior review history. The local run record stores the minimum non-secret provenance required by the canonical run contract—provider, adapter version, model, endpoint identity without credentials, generation parameters, data-category disclosure, request time, outcome, and available usage or limit metadata—not a duplicate raw outbound payload. | Must | Accepted | Payload and run-record inspection |
| REQ-SEC-016 | Authentication, quota, rate-limit, network, and provider failures must remain distinguishable. The MVP performs no automatic provider resubmission. After any provider failure or ambiguous outcome, an explicit user retry creates a new run in the same selected mode; it never crosses to or from the local provider automatically. | Must | Accepted | Failure-injection, new-run retry, and no-fallback check |
| REQ-SEC-017 | Local-runtime and model acquisition may use non-loopback networking only as a distinct user-initiated action after its destination, purpose, and expected transfer are disclosed. There is no installer network action in the MVP, and setup consent never authorizes later generation egress. | Must | Accepted | Setup and network inspection |
| REQ-SEC-018 | The application service must bind only to an enumerated loopback address and reject unapproved host, origin, cross-site, and DNS-rebinding access. State-changing browser requests require the minimum local session and request-forgery protection selected during implementation; bootstrap secrets must not appear in URLs or logs. | Must | Accepted | Local-service security checks |
| REQ-SEC-019 | Browser-delivered UI code must not receive credentials or expose direct filesystem, process-control, provider, model-runtime, vector-store, or browser-automation access. Target content, scanner output, corpus passages, and generated content must be treated as untrusted and rendered as text unless a separately accepted sandboxing and sanitization design applies. UI assets must be local and constrained by the approved content-security policy. | Must | Accepted | Renderer-boundary, XSS, CSP, and secret-leak tests |
| REQ-SEC-020 | Before React rendering, untrusted scanner, target, corpus, provider, and persisted data must be projected into a closed application-owned view model with exhaustive state handling. The renderer must not use untrusted HTML, `srcdoc`, executable URLs, or navigation targets, use untrusted values as DOM identifiers, or spread untrusted objects into element properties; unavailable actions and links must remain inert with an accessible explanation. | Must | Proposed | Projection-schema, XSS, navigation, and exhaustive-state tests |
| REQ-SEC-021 | MVP diagnostics and portfolio summaries must be local, content-safe, and limited to closed fields needed to understand a run or failure. Raw browser sessions, page captures, provider payloads, model responses, prompts, screenshots, telemetry, analytics, hosted traces, and private journals must not be copied into tracked documentation or public evidence. | Must | Accepted | Local-record and repository inspection |

## Groq privacy source basis

The Groq boundary was checked on 2026-08-25 against Groq's primary [security-onboarding guidance](https://console.groq.com/docs/production-readiness/security-onboarding) and [Your Data documentation](https://console.groq.com/docs/your-data). Provider documentation describes provider-side handling; the application must still minimize the payload, disclose that an external service receives it, and avoid claims that local deletion controls provider-side records.
