# Reliability, reproducibility, and operations requirements

## Authority and use

This document is a focused canonical module within [Quality, security, and operations requirements](README.md) and the authoritative requirements baseline indexed by [Project requirements](../../PROJECT_REQUIREMENTS.md). The index defines status vocabulary, priority semantics, ID stability, and precedence. This file describes planned behavior, not implemented behavior; each identified row's recorded status controls.

The three-scenario MVP remains limited to project-owned synthetic controlled fixtures. Live-target intake, link discovery, crawling, and a crawler implementation are not reliability obligations for this slice; adding any of them requires a later explicit scope and threat-model decision.

The proposed benchmark protocol is proportional to the claim:

- Pending OD-009, the first portfolio pilot proposes the shared 9–12-case three-scenario evaluation set, repeats each deterministic failing and corrected fixture scan three times under its exact scenario/rule profile, and records bounded descriptive observations for the selected local configuration. For contrast, it also records the emitted measured/expected ratios, colors, font size/weight, and comparison-profile identity needed to reproduce the ordered margin. It records material software/model identities, fixture and corpus size, input/output size, elapsed stage times, and readily observable peak resource use. These observations are non-promotable calibration evidence, not performance, support, or release claims.
- A later exploratory performance comparison may add explicitly defined cold and warm repetitions and report descriptive p50 and range, but it must not infer a p95 gate from a small sample.
- A performance, support, or release claim must define its measurement environment, workload, repetitions, metrics, uncertainty, thermal conditions, failure behavior, and acceptance budgets before execution. Counts such as 20 cold, 100 warm, or 30 sustained runs are introduced only when justified by that claim and are not first-slice requirements.
- Any expanded protocol records the applicable operating-system, driver, runtime, artifact, offload, power, corpus, index, fixture, browser/scanner, token, generation, concurrency, latency, throughput, memory/storage, thermal, and fallback facts needed to reproduce the claimed result.
