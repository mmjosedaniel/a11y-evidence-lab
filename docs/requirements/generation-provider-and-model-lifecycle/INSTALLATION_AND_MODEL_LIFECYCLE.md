# Installation and model lifecycle requirements

## Authority and use

This document is a focused canonical module within [Generation provider and model lifecycle requirements](README.md) and the authoritative requirements baseline indexed by [Project requirements](../../PROJECT_REQUIREMENTS.md). The index defines status vocabulary, priority semantics, ID stability, and precedence. This file describes planned behavior, not implemented behavior; each identified row's recorded status controls.

## MVP startup, model setup, and deferred packaging

**Decision status:** [ADR-0002](../../architecture/decisions/ADR-0002-windows-installation-and-model-acquisition.md) records the former Accepted Windows-installer direction. [ADR-0015](../../architecture/decisions/ADR-0015-localhost-browser-mvp-execution.md) explicitly supersedes that direction for the MVP: the application is a local service on the developer's machine, and the user opens its loopback URL in an installed Chrome or Edge browser. Installer, native wrapper, Start-menu integration, embedded webview, and distributable packaging work are Deferred. [ADR-0020](../../architecture/decisions/ADR-0020-manual-developer-managed-local-model-setup.md) further narrows the MVP: the developer installs Ollama and pulls `embeddinggemma` for retrieval in either generation mode and, when Local generation is used, `qwen3.5:4b`, all outside A11y Evidence Lab. The application neither initiates nor manages model acquisition. Model artifacts remain outside the repository and any future base installer.

| ID | Requirement | Priority | Status | Planned verification |
| --- | --- | --- | --- | --- |
| REQ-INST-001 | A Windows installer, installed launcher, Start-menu entry, registered uninstaller, native wrapper, and equivalent distributable packaging are outside the MVP. A later product need requires a new packaging decision; the historical ADR-0002 decision does not reactivate automatically. | May | Deferred | Scope and decision-history review |
| REQ-INST-002 | For the MVP, the developer starts the application-local service and opens its enumerated loopback URL in an installed Chrome or Edge browser. The service must report readiness and startup failure and provide a clean stop path. The MVP does not require an application-controlled window, embedded webview, automatic browser launch, launcher, or duplicate-instance manager. | Must | Accepted | Local startup and shutdown demonstration |
| REQ-INST-003 | Large generation and embedding model artifacts must remain outside Git, the application repository, and any future base installer. The developer acquires required local artifacts through the selected runtime outside A11y Evidence Lab after implementation is authorized. | Must | Accepted and narrowed through ADR-0020 | Repository and developer-setup inspection |
| REQ-INST-004 | AI configuration must remain separate from the global PageAnalysisRun mode selection governed by `REQ-LLM-002`. The developer may configure the approved local endpoint and model identity, configure the Groq credential, or defer generation setup; configuration neither selects a mode nor invokes a provider. A11y Evidence Lab does not install a runtime, download a model, or perform a provider connection probe during setup or mode selection. Provider availability affects only an explicit finding-specific generation attempt and never the provider-independent scan. | Must | Accepted and narrowed through ADR-0020 | Configuration, selection-separation, and no-probe demonstration |
| REQ-INST-005 | When the user explicitly starts local generation for an eligible selected finding, the local service must check that the approved Ollama loopback endpoint is reachable and that the configured `qwen3.5:4b` model is present, then use the actual generation request and runtime output validation to determine the attempt's result. A missing runtime or model fails that FindingWorkflow visibly without blocking deterministic scanning, evidence inspection, or existing local records. No earlier or separate readiness probe is required. | Must | Accepted and narrowed through ADR-0020 | Explicit-attempt, missing-runtime, missing-model, and degraded-mode checks |
| REQ-INST-006 | For MVP retrieval in either generation mode, the developer must install Ollama and pull `embeddinggemma` outside A11y Evidence Lab by following the official Ollama Windows and CLI instructions. Before Local generation, the developer must additionally pull `qwen3.5:4b` outside A11y Evidence Lab; Groq generation instead requires the configured Groq credential. The application may identify a missing prerequisite and link to the applicable instructions, but it must not invoke runtime installation, model pull, update, removal, or another model-management operation. These local artifacts are fixed evaluation prerequisites: replacing one after a failed applicable evaluation requires a new recorded model-selection decision and corresponding exact-model requirement and evaluation-configuration updates before evaluation continues, not a generic model selector or runtime fallback. Runtime and model-store ownership remain with the developer and Ollama. | Must | Accepted and narrowed through ADR-0020 | Conditional manual-prerequisite, replacement-decision, and no-managed-acquisition inspection |
| REQ-INST-007 | Historical requirement: before initiating a local-model download through the selected runtime, the UI was to show the model's purpose, source, license reference, exact tag and digest when available, expected transfer size, estimated installed storage, runtime-owned storage location when known, and practical hardware guidance, then require affirmative consent and report bounded progress, completion, and failure information. | Must | Superseded by `REQ-INST-006` and `REQ-INST-017` through ADR-0020 | Decision-history inspection |
| REQ-INST-008 | An application-owned downloader with resume, partial-artifact staging, integrity promotion, cleanup, and recovery is Deferred pending a demonstrated need beyond selected-runtime acquisition. | May | Deferred | Scope inspection |
| REQ-INST-009 | Offline artifact provisioning and import are Deferred pending a demonstrated offline-setup need. | Should | Deferred | Scope review |
| REQ-INST-010 | A comprehensive in-application model manager for verification, selection, update, removal, and storage administration is Deferred pending a demonstrated administration need. | May | Deferred | Scope review |
| REQ-INST-011 | Packaged application upgrade and uninstall data handling are Deferred with packaging. A future decision must distinguish application files, run data, credentials, runtime-managed models, and independently installed runtimes. | May | Deferred | Future packaging review |
| REQ-INST-012 | Per-user installer behavior, code signing, and update authentication are Deferred with packaging and must not be claimed for the MVP. | May | Deferred | Public-claim review |
| REQ-INST-013 | Historical requirement: browser-originated local-model acquisition requests were to name only an application-approved profile and explicit intent, while download URLs, hashes, executable paths, extraction roots, destinations, and the model store remained outside browser authority. | Must | Superseded by `REQ-INST-017` through ADR-0020 | Decision-history inspection |
| REQ-INST-014 | Historical requirement: the application-managed local-model lifecycle was limited to **not installed**, **downloading**, **ready**, or **failed**, with an explicit retry and no partial model activation. | Must | Superseded by `REQ-INST-017` through ADR-0020 | Decision-history inspection |
| REQ-INST-015 | A general application-owned acquisition system with redirect policies, byte ceilings, isolated staging, archive containment, imports, and atomic promotion is Deferred pending a demonstrated need beyond the selected-runtime boundary. | May | Deferred | Scope review |
| REQ-INST-016 | Direct application deletion of runtime-owned model stores and packaged uninstall cleanup are Deferred. Any later model removal must use an approved runtime operation or explicit user instructions, never recursive application filesystem deletion of an external store. | May | Deferred | Scope and safety review |
| REQ-INST-017 | The MVP has no application-owned runtime or model-acquisition workflow, download command, progress UI, download-state record, model manager, or acquisition retry. The application checks `embeddinggemma` only when retrieval is requested and `qwen3.5:4b` only when an explicit Local generation attempt begins. Missing setup produces a concise failure with official setup guidance; completing the prerequisite remains a developer action outside the application. | Must | Accepted through ADR-0020 and OD-022 | No-managed-acquisition and actual-use inspection |
