# Installation and model lifecycle requirements

## Authority and use

This document is a focused canonical module within [Generation provider and model lifecycle requirements](README.md) and the authoritative requirements baseline indexed by [Project requirements](../../PROJECT_REQUIREMENTS.md). The index defines status vocabulary, priority semantics, ID stability, and precedence. This file describes planned behavior, not implemented behavior; each identified row's recorded status controls.

## MVP startup, model setup, and deferred packaging

**Decision status:** [ADR-0002](../../architecture/decisions/ADR-0002-windows-installation-and-model-acquisition.md) records the former Accepted Windows-installer direction. [ADR-0015](../../architecture/decisions/ADR-0015-localhost-browser-mvp-execution.md) explicitly supersedes that direction for the MVP: the application is a local service on the developer's machine, and the user opens its loopback URL in an installed Chrome or Edge browser. Installer, native wrapper, Start-menu integration, embedded webview, and distributable packaging work are Deferred. The independent decisions to keep model artifacts outside the repository and any future installer, and to require an explicit user-initiated model download, remain Accepted.

| ID | Requirement | Priority | Status | Planned verification |
| --- | --- | --- | --- | --- |
| REQ-INST-001 | A Windows installer, installed launcher, Start-menu entry, registered uninstaller, native wrapper, and equivalent distributable packaging are outside the MVP. A later product need requires a new packaging decision; the historical ADR-0002 decision does not reactivate automatically. | May | Deferred | Scope and decision-history review |
| REQ-INST-002 | For the MVP, the developer starts the application-local service and opens its enumerated loopback URL in an installed Chrome or Edge browser. The service must report readiness and startup failure and provide a clean stop path. The MVP does not require an application-controlled window, embedded webview, automatic browser launch, launcher, or duplicate-instance manager. | Must | Accepted | Local startup and shutdown demonstration |
| REQ-INST-003 | Large generation and embedding model artifacts must remain outside Git, the application repository, and any future base installer. Acquiring a local model is a separate explicit action performed through the selected local runtime after implementation is authorized. | Must | Accepted | Repository and acquisition-flow inspection |
| REQ-INST-004 | AI setup must remain explicit and separate from the global PageAnalysisRun mode selection governed by `REQ-LLM-002`. The user may configure the selected local runtime, configure Groq, or defer generation setup; inspecting or changing setup does not select a mode or invoke a provider. Provider readiness gates only an explicit finding-specific generation call and never the provider-independent scan. Setup must not install, download, or transmit anything until the user chooses the action and consents. | Must | Accepted | Setup, selection separation, degraded-mode, and network-behavior demonstration |
| REQ-INST-005 | Before local generation, the local service must verify that the selected runtime is reachable on its approved loopback endpoint, the selected model is present, and the adapter's mandatory capabilities are available. A failure makes local generation unavailable for that run but does not block deterministic scanning, evidence inspection, or existing local records; those capabilities remain usable even when neither generation provider is ready. | Must | Accepted | Missing-runtime, missing-model, and degraded-mode checks |
| REQ-INST-006 | If the selected runtime is absent or incompatible, the MVP may provide official instructions or a link to the approved source but must not silently install or update a third-party runtime. Runtime installation ownership remains with the user and the runtime vendor. | Must | Accepted | Missing-runtime and no-silent-install inspection |
| REQ-INST-007 | Before initiating a local-model download through the selected runtime, the UI must show the model's purpose, source, license reference, exact tag and digest when available, expected transfer size, estimated installed storage, runtime-owned storage location when known, and practical hardware guidance, then require affirmative consent. The MVP delegates acquisition mechanics to that runtime and reports its bounded progress, completion, and failure information when available. | Must | Accepted | Disclosure, consent, and acquisition-boundary inspection |
| REQ-INST-008 | An application-owned downloader with resume, partial-artifact staging, integrity promotion, cleanup, and recovery is Deferred pending a demonstrated need beyond selected-runtime acquisition. | May | Deferred | Scope inspection |
| REQ-INST-009 | Offline artifact provisioning and import are Deferred pending a demonstrated offline-setup need. | Should | Deferred | Scope review |
| REQ-INST-010 | A comprehensive in-application model manager for verification, selection, update, removal, and storage administration is Deferred pending a demonstrated administration need. | May | Deferred | Scope review |
| REQ-INST-011 | Packaged application upgrade and uninstall data handling are Deferred with packaging. A future decision must distinguish application files, run data, credentials, runtime-managed models, and independently installed runtimes. | May | Deferred | Future packaging review |
| REQ-INST-012 | Per-user installer behavior, code signing, and update authentication are Deferred with packaging and must not be claimed for the MVP. | May | Deferred | Public-claim review |
| REQ-INST-013 | Local-model acquisition requests from the browser must name only an application-approved local profile and explicit intent. Download URLs, hashes, executable paths, extraction roots, and arbitrary destinations must remain owned by the local service or selected runtime, never supplied by browser code. The application must not create a competing model store and may invoke only the approved selected-runtime operation for the selected profile after REQ-INST-007 disclosure and consent. | Must | Accepted | Renderer-boundary and adapter inspection |
| REQ-INST-014 | The MVP local-model state needs only **not installed**, **downloading**, **ready**, or **failed**. Downloading does not select a generation mode, failure does not activate a partial model, and retry requires an explicit user action. Each run records only the selected profile and observed model identity it needs; the selected runtime owns its model store. More detailed cancellation, resume, verification, import, update, and promotion states are Deferred. | Must | Accepted | State-transition and run-record inspection |
| REQ-INST-015 | A general application-owned acquisition system with redirect policies, byte ceilings, isolated staging, archive containment, imports, and atomic promotion is Deferred pending a demonstrated need beyond the selected-runtime boundary. | May | Deferred | Scope review |
| REQ-INST-016 | Direct application deletion of runtime-owned model stores and packaged uninstall cleanup are Deferred. Any later model removal must use an approved runtime operation or explicit user instructions, never recursive application filesystem deletion of an external store. | May | Deferred | Scope and safety review |
